# granki-bench

Оценка качества русского текста — статьи, главы, книги, написанных человеком или с ИИ — по зафиксированной и проверенной методике.

Запускаете одну команду на своём тексте и получаете отчёт:

- **качество** — баллы 0–100 по группам (языковая правильность, чистота, шаблонность, конкретика, логика и структура, польза) и общий балл качества; балл — положение относительно текстов того же жанра, а не оценка «на глаз»;
- **похожесть на текст ИИ** — отдельный показатель 0–100 с измеренной долей ложных срабатываний на человеческих текстах; не вердикт «написано ИИ»;
- **стиль** — профиль текста относительно жанра: где текст выделяется;
- **рекомендации** — с цитатой, объяснением и примером исправления.

Нужна одна подписка — Claude или Codex. Без модели работают метрики, правила и детектор.

> **Статус: разработка.** Есть протокол `v1` — протокол пилота Granki как есть — и 39 его результатов. Описанный выше отчёт — цель методики `v2`, она в работе: оценки до первой версии не сравнимы с будущими.

## Зачем

Оценку текстов моделями-судьями трудно повторить: промпты теряются, модели меняются за тем же названием, а сами судьи на литературном качестве ненадёжны. granki-bench фиксирует методику так, чтобы оценки разных лет можно было сравнивать, и проверяет её на корпусе настоящих текстов, а не на текстах, написанных моделью.

Бенчмарк появился из пилота [Granki](https://github.com/apantin/granki) — набора агентных скиллов для русскоязычных статей по данным, — но оценивает любые тексты.

## Принципы

- **Протоколы с версиями.** Протокол — промпты, критерии, формула счёта, состав судей. Выпущенный протокол не меняется, любая правка — новая версия. `v1` — протокол пилота Granki как есть, `v2` — первая проверенная методика.
- **Устойчивость к модели.** Результат не должен зависеть от того, какой моделью судили. У пользователя один судья — Claude или Codex через их CLI; что они взаимозаменяемы, проверяется при разработке на многих моделях. В отчёте — ожидаемая погрешность судьи, измеренная при проверке, и поправка из калибровочной таблицы для его модели.
- **Баллы вычисляются, а не спрашиваются у судьи:** метрика — перцентиль в жанре, критерий судьи — доля выполненных пунктов бинарного чек-листа с цитатами.
- **Сравнимость держится на текстах.** Эталонные тексты заморожены, детерминированные метрики воспроизводимы точно, судьи регулярно калибруются на эталонах.
- **Метрики отбираются по данным, проверка — до выпуска.** Критерии отбора и пороги проверки записываются заранее; проверка — на данных, которых не видели при разработке, итог — на скрытом наборе.
- **Полные метаданные** в каждом результате: версия протокола, хеш промпта, модель, версия CLI, версия калибровки, хеши текстов, версия корпуса, коммит bench.

## Что меряем

Набор метрик окончательно определится по итогам замеров; ниже — что заложено.

| Блок | Чем |
|---|---|
| Качество | Языковая правильность: типографика (свои правила), орфография и грамматика (LanguageTool, необязательно); чистота (канцелярит, штампы, вода) — правила с объяснением и советом; шаблонность и ритм относительно жанровой нормы; конкретика; логика, структура и польза — чек-листы судей |
| Похожесть на ИИ | Классификатор на признаках текста, обученный на человеческих текстах жанров и текстах многих моделей |
| Стиль | Профиль текста относительно жанра: длина предложений, номинализации, пассив, первое лицо, пунктуация и др. |

## Быстрый старт (протокол `v1`)

Сейчас работает только протокол пилота `v1`: у него четыре судьи, поэтому нужны обе подписки. Нужны Python 3.10+ и CLI судей: [Claude Code](https://docs.claude.com/en/docs/claude-code) и [Codex CLI](https://github.com/openai/codex), с выполненным входом. Зависимостей нет.

```bash
# пара пилота Granki одной командой (протокол v1, все четыре судьи)
python3 -m bench pair --anchors anchors/pilot-2026-11 --pair E5-vs-E4 --out result.json

# свои тексты, выбранные судьи
python3 -m bench pair A.md B.md --posts posts.md --reader "кто читатель" --judges opus,codex --out result.json

# абсолютная оценка, счётчик маркеров, пересчёт итога, проверка эталонов
python3 -m bench score article.md --posts posts.md --claims data.csv --reader "…" --out score.json
python3 -m bench markers article.md --ref posts.md
python3 -m bench recompute results/v1-pilot-2026-11/*.json
python3 -m bench verify anchors/pilot-2026-11
```

В результате — итог по критериям, голоса с точной моделью каждого судьи и **разброс между моделями** (`spread`), плюс версия протокола, хеш промпта, версии CLI и коммит bench.

## Структура

| Путь | Что |
|---|---|
| `protocols/v1/` | Протокол пилота Granki: промпты дословно, критерии, формула счёта, судьи; [известные недостатки](protocols/v1/README.md) |
| `bench/` | Код: адаптеры Claude Code и Codex, парное сравнение, абсолютная оценка, счёт и разброс, счётчик маркеров v1 |
| `anchors/pilot-2026-11/` | Эталоны: тексты пилота, посты-эталон, данные; манифест с хешами; 31 пара |
| `results/v1-pilot-2026-11/` | 39 результатов пилота в формате bench ([поля](results/README.md)) |
| `scripts/` | Импорт пилота, проверка перед коммитом |
| `tests/` | Тесты без вызовов моделей: `python3 -m unittest discover -s tests` |

Дальше появятся `protocols/v2/`, `docs/methodology.md`, `docs/validation.md` и правила качества в `rules/`.

## Разработка

Включить проверку перед коммитом: `git config core.hooksPath .githooks`. Она не пропускает файлы вне разрешённых папок, файлы данных вне `anchors/`, посторонние файлы в `results/`, локальные пути и адреса почты, файлы больше 5 МБ, эталоны, не совпавшие с манифестом, и правку замороженных промптов.

Экспериментальная очистка: [шапка Blogspot-поста v21](docs/blogspot-post.md),
[индексы и типизированный код v20](docs/technical-markup.md),
[кандидат издательских ролей v19](docs/publication-cleanup.md),
явные импорты `bench.candidates.technical_markup.extract` и
`bench.candidates.publication_cleanup.extract`. Старые версии и
очистка по умолчанию не переключаются.

## План

1. ✅ Основа: протокол пилота Granki как `v1`, эталонные тексты и результаты пилота.
2. ✅ Рамка: сценарий, отчёт, баллы, судьи, порядок работ.
3. Данные первого жанра (статья, блог, технический текст): корпус — [granki-corpus](https://github.com/apantin/granki-corpus), пары «хуже — лучше», тексты моделей.
4. Срезы методики по группам, от дешёвого к дорогому: детерминированные метрики → правила и LanguageTool → детектор ИИ → чек-листы судей. Каждый срез: кандидаты → замеры → отбор по заранее записанным критериям → проверка на невиденных данных.
5. Сборка первого жанра и протокол `v2`.
6. Следующие жанры: нехудожественная книга и научпоп, научный и технический текст, новости, художественная проза.
7. Первая версия.
8. Исследование и рейтинг моделей — как судей и как авторов.

Итоговые замеры делаются и на скрытом проверочном наборе, чтобы методику и тексты не подгоняли под публичные данные.

## Данные

Публичный корпус — в отдельном репозитории [granki-corpus](https://github.com/apantin/granki-corpus): у каждого текста свой источник и лицензия. Путь к данным передаётся bench параметром.
