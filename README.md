# granki-bench

Бенчмарк русского текста по двум осям:

- **стиль** — насколько текст похож на тексты целевого автора или жанра;
- **качество** — насколько текст хорош сам по себе: ясен, логичен, точен, полезен читателю, без мусора.

Оси не сводятся в одно число. Плохой текст в стиле автора остаётся текстом автора, но отчёт говорит, что он плохой; хороший текст чужим голосом — хороший, но не авторский. Если дефект качества совпадает с чертой автора, отчёт показывает его как дефект с пометкой «соответствует стилю автора».

> **Статус: разработка.** Есть протокол `v1` — протокол пилота Granki как есть — и 39 его результатов. Проверенной методики (`v2`) ещё нет: оценки до первой версии не сравнимы с будущими.

## Зачем

Оценку текстов моделями-судьями трудно повторить: промпты теряются, модели меняются за тем же названием, а сами судьи на литературном качестве ненадёжны. granki-bench фиксирует методику так, чтобы оценки разных лет можно было сравнивать, и проверяет её на корпусе настоящих текстов, а не на текстах, написанных моделью.

Бенчмарк появился из пилота [Granki](https://github.com/apantin/granki) — набора агентных скиллов для русскоязычных статей по данным, — но оценивает любые тексты.

## Принципы

- **Протоколы с версиями.** Протокол — промпты, критерии, формула счёта, состав судей. Выпущенный протокол не меняется, любая правка — новая версия. `v1` — протокол пилота Granki как есть, `v2` — первая проверенная методика.
- **Устойчивость к модели.** Результат не должен зависеть от того, какой моделью судили. **Разброс оценок между моделями — метрика наравне с самими оценками:** низкий разброс — оценке можно верить, высокий — критерий на этом тексте спорный.
- **Судьи по умолчанию — общедоступные модели Claude и Codex** через их CLI: без своих серверов и без отдельных ключей API. Другие модели — для проверки устойчивости и рейтинга моделей.
- **Сравнимость держится на текстах.** Новые версии сравниваются с замороженными эталонными текстами, а не с сохранёнными числами; детерминированные метрики воспроизводимы точно.
- **Методика до кода, проверка до выпуска.** Критерии проверки методики записываются заранее, вместе с порогами.
- **Полные метаданные** в каждом результате: версия протокола, хеш промпта, модели, версии CLI, хеши текстов, версия корпуса, коммит bench.

## Что меряем

| Ось | Чем |
|---|---|
| Стиль | Стилометрия (Delta по частым словам, символьные n-граммы) на шкале «другой автор того же жанра — автор сам с собой»; карта дрейфа признаков; парное сравнение судьями «какой ближе к голосу автора» |
| Качество | Языковая правильность; чистота (канцелярит, штампы, вода) — правила с объяснением и советом; шаблонность относительно жанровой нормы; конкретика; логика, структура и польза — чек-листы судей; точность и честность — когда к тексту приложены данные |

## Быстрый старт

Нужны Python 3.10+ и CLI судей: [Claude Code](https://docs.claude.com/en/docs/claude-code) и [Codex CLI](https://github.com/openai/codex), с выполненным входом. Зависимостей нет.

```bash
# пара пилота Granki одной командой (протокол v1, все четыре судьи)
python3 -m bench pair --anchors anchors/pilot-2026-11 --pair E5-vs-E4 --out result.json

# свои тексты, выбранные судьи
python3 -m bench pair A.md B.md --posts posts.md --reader "кто читатель" --judges opus,codex --out result.json

# абсолютная оценка, счётчик маркеров, пересчёт итога, проверка эталонов
python3 -m bench score article.md --posts posts.md --claims data.csv --reader "…" --out score.json
python3 -m bench markers article.md --ref posts.md
python3 -m bench recompute results/v1-pilot-2026-11/*.json
python3 -m bench verify anchors/pilot-2026-11
```

В результате — итог по критериям, голоса с точной моделью каждого судьи и **разброс между моделями** (`spread`), плюс версия протокола, хеш промпта, версии CLI и коммит bench.

## Структура

| Путь | Что |
|---|---|
| `protocols/v1/` | Протокол пилота Granki: промпты дословно, критерии, формула счёта, судьи; [известные недостатки](protocols/v1/README.md) |
| `bench/` | Код: адаптеры Claude Code и Codex, парное сравнение, абсолютная оценка, счёт и разброс, счётчик маркеров v1 |
| `anchors/pilot-2026-11/` | Эталоны: тексты пилота, посты-эталон, данные; манифест с хешами; 31 пара |
| `results/v1-pilot-2026-11/` | 39 результатов пилота в формате bench ([поля](results/README.md)) |
| `scripts/` | Импорт пилота, проверка перед коммитом |
| `tests/` | Тесты без вызовов моделей: `python3 -m unittest discover -s tests` |

Дальше появятся `protocols/v2/`, `docs/methodology.md`, `docs/validation.md` и правила качества в `rules/`.

## Разработка

Включить проверку перед коммитом: `git config core.hooksPath .githooks`. Она не пропускает файлы вне разрешённых папок, локальные пути и адреса почты, файлы больше 5 МБ, эталоны, не совпавшие с манифестом, и правку замороженных промптов.

## План

1. ✅ Основа: протокол пилота Granki как `v1`, эталонные тексты и результаты пилота.
2. Методика `v2` по обзорам литературы.
3. Корпус — [granki-corpus](https://github.com/apantin/granki-corpus).
4. Реализация.
5. Проверка методики и корректировка.
6. Первая версия.
7. Исследование стилей и рейтинг моделей — как судей и как авторов.

Итоговые замеры делаются и на скрытом проверочном наборе, чтобы методику и тексты не подгоняли под публичные данные.

## Данные

Публичный корпус — в отдельном репозитории [granki-corpus](https://github.com/apantin/granki-corpus): у каждого текста свой источник и лицензия. Путь к данным передаётся bench параметром.
